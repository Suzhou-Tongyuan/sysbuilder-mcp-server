# 📘 Sysbuilder SysML 自动建模规范（标准版）

## 一、目标软件

- **软件名称**：Sysbuilder  
- **路径输入规则**：所有文件路径输入统一使用 `//`

### 必须：
- 必须使用 UTF-8 编码 Python 脚本，该要求为强制执行项
- 凡新增、修改、执行的 Sysbuilder 建模脚本，必须先确认脚本文件本身为 UTF-8 编码后再运行
- 凡涉及 Sysbuilder 的自动化建模、Modelica 生成、报告生成脚本，若不是 UTF-8 编码，必须先修正后执行，禁止跳过
---

## 二、总体执行原则

1. **必须执行优先，不停留解释**
   - 所有任务直接进入建模执行流程
   - 禁止只描述不操作
   - 禁止将“最小联通验证”作为独立前置步骤；除非为处理异常，否则应直接执行正式建模流程

2. **禁止反复迭代脚本，优先向下推进**
   - 正式建模执行过程中，若遇到局部步骤失败，应优先保持主线继续向下推进
   - 禁止围绕同一局部问题反复改脚本、反复从头重跑
   - 应优先完成主体模型、关键视图、Modelica 生成与报告生成，再对残留局部问题补充说明
   - 若某一步确实无法继续，需明确说明阻塞点，而不是进入无休止脚本迭代
3. **建模前必须先启动或连接 Sysbuilder**
   - 要进行建模，必须先调用 `StartSysbuilder` 打开软件
   - 如果 `StartSysbuilder` 打开软件失败，必须继续调用 `FindSysbuilder`
   - 如果 `FindSysbuilder` 找到可用的 Sysbuilder 实例，必须调用 `ConnectSysbuilder` 连接可用实例后再继续建模
   - 仅当 `StartSysbuilder` 与 `FindSysbuilder` / `ConnectSysbuilder` 都失败时，才允许报告软件启动或连接阻塞
4. **建模失败，不保存，重新再建模**
5. **所有中间文件生成到output文件夹**
6. **不做联通检查，直接写脚本运行软件**
7. **模型没有根元素名，直接从包开始新建**

## 三、工程管理规范

### 3.1 新建工程

- 新建模型前必须执行：
  - ✅ 新建工程
- 工程文件：
  - 后缀：`.sybprojz`
- 存储规则：
  - 若未指定路径 → 使用 Sysbuilder 工作目录
- 工程名与元素全名规则：
  - ❗ 元素全名必须从 **工程内顶层元素** 开始书写
  - ❌ 不要写成 `工程名.模型名.元素名`
  - ✅ 应写成 `模型名.元素名`
  - 例如：根包创建应使用 `固体发动机系统模型`
  - 例如：子元素创建应使用 `固体发动机系统模型.需求模型`

|--------|-------------|

## 六、需求建模规范

### 6.1 需求分层结构

顶层需求建议包含：

- 功能需求  
- 性能需求  
- 集成接口需求  
- 通用质量特性需求  

需求建议新建指标

---

### 6.2 子需求

- 每个顶层需求下：
  - 建议创建子需求（分层）
- 创建方式要求：
  - ✅ 应直接按父需求路径创建子需求
  - ✅ 推荐写法：`模型名.需求模型.功能需求.点火功能需求`
  - ❌ 不要先创建为同级需求，再依赖后续 `Containment` 调整层级
- 原因说明：
  - 在 Sysbuilder 中，若先创建为平级需求，再建立 `Containment`，子需求的实际全名会变为 `父需求.子需求`
  - 若脚本仍使用旧路径创建 `Satisfy`、`Verify`、`Trace` 等关系，会出现“元素不存在”错误
- 执行约束：
  - 建立需求关系前，必须以最终层级路径作为需求全名

---

### 6.3 需求关系

必须建立：

- 包含关系（Containment）  
- 满足关系（Satisfy）：
  满足关系是活动或者块连接到需求
  每个需求建议都有满足连线
- 路径校验要求：
  - 在创建 `Satisfy` 前，必须确认需求元素路径已经是包含关系建立后的最终路径
  - 若需求存在父子分层，连线目标应写为完整分层路径，而不是创建前的平级路径

---

## 七、活动建模规范

### 7.1 活动分层

- 活动必须支持：
  - 子活动结构  
- 活动图挂载要求：
  - ✅ 活动图优先创建在顶层活动下，采用“顶层活动 + 子活动图”的方式组织
  - ✅ 推荐写法：先创建 `模型名.行为模型.固体发动机推进流程`，再创建 `模型名.行为模型.固体发动机推进流程.固体发动机推进活动图`
  - ❌ 不建议直接在行为包下创建活动图后再向图中插入活动
- 执行约束：
  - 自动建模时，必须先创建承载该图的顶层活动，再创建对应子活动图
  - 若活动图创建成功但无法插入活动元素，应优先检查活动图是否挂载在活动节点下，而不是继续重试插入
---

### 7.2 脚本规则（关键）

| 类型 | 规则 |
|------|------|
| 普通活动 | 可设置脚本 |
| 子活动图 | ❗ 与脚本互斥 |
| 不透明行为 | ✅ 必须设置脚本 |

---

### 7.3 状态机要求

- 不透明行为需设置为：
  - entry  
  - do  
  - exit  

---

## 八、块（Block）建模规范

### 8.1 块结构

- 每个块：
  - 建议包含 **代理端口**
- 代理端口创建规则：
  - ❗ **不能直接创建在组成属性下面**
  - ✅ 必须先创建在 **块类型** 上
  - ✅ 再由部件实例在 **IBD** 中继承使用
- 值属性
  - 建议设置默认值、设置单位、设置基础数据类型（Real\Integer\String\Boolean）
- 新建组成属性有两种方式，优先考虑第一种
-   第一种是在模块定义图中建立组合连线
-   第二种是新建组成属性元素

---

### 8.2 分配关系

必须建立：

- 活动 → 块 分配关系 
- 每个块建议都有分配关系 

实现方式：

1. 模块定义图中建立分配关系   

---

## 十、参数与约束规范

### 10.1 约束必须包含

| 内容 | 要求 |
|------|------|
| 表达式 | ✅ 必须 |
| 输入参数 | 右值 |
| 输出参数 | 左值 |

- 输入参数：
  - 建议设置默认值、设置单位、设置基础数据类型（Real\Integer\String\Boolean）

- 执行限制：
  - ❗ 输入参数和输出参数创建后，**不能再单独设置方向**
  - ❗ 约束属性下，**不能创建输入参数和输出参数**
  - ✅ 约束参数应创建在约束块下，而不是创建在约束属性下

---

### 10.2 示例结构

```
输出参数 = 表达式(输入参数)
```

## 十一、追踪与分析（必须）

系统必须创建：

1. 需求功能追溯矩阵  
2. 架构功能追溯矩阵  
3. 需求表格  
4. 架构表格  
5. 追溯分析图

👉 使用 Sysbuilder API 专用接口
- 创建规则：
  - ✅ 应先切换或定位到目标追踪分析包
  - ✅ 调用接口时只传图名，不传完整路径
  - ✅ 推荐做法：先创建独立追踪分析包，再在该包下创建表格/矩阵

### 11.2 执行约束

- 使用追踪分析专用接口前，必须先确认当前创建上下文已定位到目标包
- 若专用接口返回路径相关错误，应优先检查是否误传完整路径，而不是重复创建同名视图
