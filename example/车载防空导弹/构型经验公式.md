# 构型经验公式

| 项目 | 内容 |
| --- | --- |
| 文档定位 | 阶段 A 四构型初步筛选经验公式 |
| 参考文件 | `03_详细设计/模型架构/车载防空导弹详细设计方案发布版.md` |
| 适用对象 | `CFG-A/B/C/D` 四种演示构型 |
| 适用阶段 | 单弹单目标基准工况下的方案初筛、评审复核和结果解释 |
| 使用边界 | 仅用于本案例数字样机和脱敏演示参数筛选，不代表真实装备性能，不用于真实武器设计、部署或作战决策 |

## 1. 构型对象

阶段 A 的四种构型只改变动力拓扑、气动布局和少量演示参数，目标、环境、初始条件、发射口径和评价阈值保持一致。

| 构型 | 构型编号 | 动力拓扑 | 气动布局 | 初筛理解 |
| --- | ---: | --- | --- | --- |
| `CFG-A` | 1 | 助推-续航 | 尾舵/尾翼 | 公开基线起点，参数完整度和模型成熟度最高 |
| `CFG-B` | 2 | 双脉冲 | 尾舵/尾翼 | 用于观察动力拓扑变化对脱靶距离、速度和过载边界的影响 |
| `CFG-C` | 3 | 助推-续航 | 鸭式布局 | 用于观察气动布局变化对机动、控制指令和结构载荷的影响 |
| `CFG-D` | 4 | 双脉冲 | 鸭式布局 | 动力和气动同时变化，复杂度最高，作为组合差异验证构型 |

## 2. 初筛指标

初筛指标直接沿用发布版方案中的关键指标和阶段 A 参数。建议先做硬门槛检查，再做 0-1 归一化综合评分。

| 指标类别 | 变量 | 建议阈值 | 用途 |
| --- | --- | ---: | --- |
| 仿真有效性 | `simulationOk`, `noNaNInf` | 均为 `true` | 过滤不可运行或数值异常构型 |
| 拦截效果 | `minMissDistance` | `<= 80 m` 进入候选，`<= 30 m` 视为命中演示口径 | 评价弹目交会效果 |
| 机动边界 | `accelerationNorm` | `<= 350 m/s2` | 检查导弹等效加速度边界 |
| 过载边界 | `maxOverload` | `<= 35 g` | 检查单弹机动能力和演示边界 |
| 制导命令 | `norm(aCmd)`, `guidanceCommandChatter` | `norm(aCmd) <= 250 m/s2`，抖振阈值 `30 m/s2` | 检查控制指令是否受限且平滑 |
| 气动边界 | `mach`, `qDyn` | `mach <= 3.5`，`qDyn <= 80000 Pa` | 检查气动健康状态 |
| 结构边界 | `structureLoadRatio` | `<= 1.0` | 检查结构载荷利用率 |
| 健康状态 | `motorOk`, `structureOk`, `aeroOk`, `controlOk`, `missileCommOk`, `onboardPowerOk` | 健康项越多越好 | 评价构型集成稳定性 |
| 模型复杂度 | `modelComplexityScore` | `{1.00, 0.85, 0.85, 0.70}` | 作为同等性能下的工程成熟度偏好 |

## 3. 通用函数

为便于文档、脚本和模型实现保持一致，本文统一使用以下简单函数。

```text
clip01(x) = max(0, min(1, x))

bool01(flag) =
  if flag then 1 else 0

norm3(v) =
  sqrt(v[1]^2 + v[2]^2 + v[3]^2)
```

其中 `i` 表示构型编号，`i=1/2/3/4` 分别对应 `CFG-A/B/C/D`。

## 4. 硬门槛公式

硬门槛用于判断构型是否有资格进入候选集合。若只需与当前 Modelica 评分器完全一致，可将 `minMissDistance <= 80 m` 作为脱靶距离子评分而非硬门槛；若用于评审初筛，建议将其作为候选门槛。

```text
valid_i =
  simulationOk_i
  and noNaNInf_i

interceptCandidate_i =
  minMissDistance_i <= 80

motionBoundaryOk_i =
  accelerationNormMax_i <= 350
  and maxOverload_i <= 35

guidanceBoundaryOk_i =
  maxNormACmd_i <= 250

aeroStructureBoundaryOk_i =
  machMax_i <= 3.5
  and qDynMax_i <= 80000
  and structureLoadRatioMax_i <= 1.0

gatePass_i =
  valid_i
  and interceptCandidate_i
  and motionBoundaryOk_i
  and guidanceBoundaryOk_i
  and aeroStructureBoundaryOk_i
```

说明：

1. `gatePass_i=false` 的构型不推荐作为阶段 A 推荐构型输出。
2. 若某个边界变量暂未输出，应在记录中标记为“数据缺口”，不建议默认为通过。
3. 本公式只说明演示模型的适用范围，不推断真实装备极限。

## 5. 子评分公式

### 5.1 脱靶距离评分

脱靶距离越小越好，80 m 作为候选阈值，30 m 作为当前命中演示口径。

```text
scoreMissDistance_i =
  clip01(1 - minMissDistance_i / 80)
```

可选命中奖励项用于评审解释，不建议过度加权。

```text
hitBonus_i =
  if minMissDistance_i <= 30 then 1 else 0
```

### 5.2 制导平滑评分

制导命令抖振越小越好。

```text
scoreGuidanceCommand_i =
  clip01(1 - guidanceCommandChatter_i / 30)
```

若需要同时考虑指令幅值，可追加指令限幅裕度。

```text
scoreCommandMargin_i =
  clip01(1 - maxNormACmd_i / 250)
```

### 5.3 健康状态评分

健康状态采用 6 个布尔项平均，越接近 1 表示构型越稳定。

```text
scoreHealth_i =
  (
    bool01(motorOk_i)
    + bool01(structureOk_i)
    + bool01(aeroOk_i)
    + bool01(controlOk_i)
    + bool01(missileCommOk_i)
    + bool01(onboardPowerOk_i)
  ) / 6
```

### 5.4 模型复杂度评分

复杂度评分用于体现“同等效果下优先选择更稳定、更简单、更成熟构型”的经验偏好。

```text
modelComplexityScore =
  {1.00, 0.85, 0.85, 0.70}
```

对应关系如下。

| 构型 | 复杂度评分 |
| --- | ---: |
| `CFG-A` | 1.00 |
| `CFG-B` | 0.85 |
| `CFG-C` | 0.85 |
| `CFG-D` | 0.70 |

## 6. 综合评分公式

综合评分沿用发布版方案和当前 `ConfigurationSelectionEvaluator` 的权重口径，保持简单、可解释、可追溯。

```text
rawScore_i =
  0.40 * scoreMissDistance_i
  + 0.25 * scoreGuidanceCommand_i
  + 0.20 * scoreHealth_i
  + 0.15 * modelComplexityScore_i

configurationScore_i =
  if valid_i then rawScore_i else 0
```

推荐通过阈值：

```text
configSelectionPass_i =
  gatePass_i
  and configurationScore_i >= 0.50
```

若当前只复刻 Modelica 源码评分器，可使用下列更宽松口径：

```text
configSelectionPass_i =
  simulationOk_i
  and noNaNInf_i
  and configurationScore_i >= 0.50
```

评审初筛建议采用包含 `gatePass_i` 的严格口径；模型回归测试建议采用与源码一致的宽松口径，避免改变既有验证结果。

## 7. 排序与推荐公式

候选构型集合：

```text
CandidateSet =
  { i | configSelectionPass_i = true }
```

若候选集合非空：

```text
bestConfigId =
  arg max configurationScore_i, i in CandidateSet
```

若候选集合为空：

```text
bestConfigId = 0
stageAExitPass = false
```

平局时按以下顺序处理：

1. 优先选择 `scoreHealth_i` 更高的构型。
2. 健康状态相同，优先选择 `minMissDistance_i` 更小的构型。
3. 脱靶距离相近，优先选择 `modelComplexityScore_i` 更高的构型。
4. 仍然相同，按 `CFG-A -> CFG-B -> CFG-C -> CFG-D` 的顺序选择。

阶段 A 出口门槛：

```text
stageAExitPass =
  bestConfigId in {1, 2, 3, 4}
  and configSelectionPass[bestConfigId]
```

## 8. 仿真前资料完整性预筛

若尚未完成四构型统一仿真，只能做“资料完整性和工程成熟度”预筛，不应输出真实性能排序。

```text
preScore_i =
  0.50 * parameterCompleteness_i
  + 0.30 * topologyMaturity_i
  + 0.20 * aeroLayoutMaturity_i
```

建议取值：

| 项 | 建议取值 |
| --- | --- |
| `parameterCompleteness_i` | `1 - tbdParameterRatio_i` |
| 助推-续航 `topologyMaturity_i` | `1.00` |
| 双脉冲 `topologyMaturity_i` | `0.90` |
| 尾舵/尾翼 `aeroLayoutMaturity_i` | `1.00` |
| 鸭式布局 `aeroLayoutMaturity_i` | `0.90` |

该预筛只用于判断“是否具备进入统一仿真的资料基础”。在当前构型记录下，可作为如下经验判断：

| 构型 | `tbdParameterRatio` | 预筛理解 |
| --- | ---: | --- |
| `CFG-A` | 0.00 | 基线构型，优先作为验证起点 |
| `CFG-B` | 0.05 | 参数缺口较小，可进入统一仿真对比 |
| `CFG-C` | 0.05 | 参数缺口较小，可进入统一仿真对比 |
| `CFG-D` | 0.10 | 组合变化最多，建议重点关注数据缺口和边界裕度 |

## 9. 推荐使用流程

1. 对 `CFG-A/B/C/D` 使用同一阶段 A 单弹单目标工况。
2. 检查 `simulationOk` 和 `noNaNInf`，剔除不可用构型。
3. 检查脱靶距离、加速度、过载、制导命令、马赫数、动压和结构载荷硬门槛。
4. 计算 `scoreMissDistance`、`scoreGuidanceCommand`、`scoreHealth` 和 `modelComplexityScore`。
5. 计算 `configurationScore`，使用 `0.50` 作为初筛通过阈值。
6. 输出 `configSelectionPass[4]`、`configurationScore[4]`、`configSelectionRank[4]`、`bestConfigId` 和 `stageAExitPass`。

## 10. 一页版公式

用于报告或评审时，可直接引用以下简化版。

```text
gatePass_i =
  simulationOk_i
  and noNaNInf_i
  and minMissDistance_i <= 80
  and accelerationNormMax_i <= 350
  and maxOverload_i <= 35
  and maxNormACmd_i <= 250
  and machMax_i <= 3.5
  and qDynMax_i <= 80000
  and structureLoadRatioMax_i <= 1.0

scoreMissDistance_i =
  clip01(1 - minMissDistance_i / 80)

scoreGuidanceCommand_i =
  clip01(1 - guidanceCommandChatter_i / 30)

scoreHealth_i =
  (
    bool01(motorOk_i)
    + bool01(structureOk_i)
    + bool01(aeroOk_i)
    + bool01(controlOk_i)
    + bool01(missileCommOk_i)
    + bool01(onboardPowerOk_i)
  ) / 6

configurationScore_i =
  if simulationOk_i and noNaNInf_i then
    0.40 * scoreMissDistance_i
    + 0.25 * scoreGuidanceCommand_i
    + 0.20 * scoreHealth_i
    + 0.15 * modelComplexityScore_i
  else
    0

configSelectionPass_i =
  gatePass_i and configurationScore_i >= 0.50

bestConfigId =
  arg max configurationScore_i, i in {i | configSelectionPass_i = true}
```
