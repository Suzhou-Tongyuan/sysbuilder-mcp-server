## 1. 文档概述

### 1.1 编写目的

本文档在《车载防空导弹Modelica详细设计方案.md》的基础上，形成面向发布、评审和后续实施的详细设计方案。发布版将原方案中的“阶段 A：单弹单目标构型筛选”和“阶段 B：最佳构型全场景验证”重组为需求、架构、功能、模块、接口、数据、算法、指标、测试、交付和风险等工程化章节，便于后续按需求-设计-模型-测试链路追踪。

本发布版重点回答以下问题：

1. 演示系统要验证什么需求和指标。
2. Modelica 模型库如何分层、封装和连接。
3. 阶段 A 如何设计 `CFG-A/B/C/D` 四种构型，完成构型方案仿真筛选、标准工况验证、控制参数优化和动力等参数拉偏试验。
4. 阶段 B 如何使用 `bestConfigId` 完成海岛环境下 4 个导弹打击 2 个目标的确定性流程验证。
5. 当前已经形成哪些验证证据，哪些内容仍需后续确认。

## 2. 需求理解与设计依据

### 2.1 上层需求

上层需求采用“总-分-总”的闭合思路组织。首先，以海岛环境下 4 个导弹打击 2 个目标的大场景作为总体牵引，明确岛礁/海面环境、目标群、发射资源、探测火控、导弹装备和任务评估之间的场景级需求；其次，依据该大场景需求，将可设计、可仿真、可验证的核心能力分解到“单个导弹装备”的设计开发、构型筛选、接口封装、智能制导控制、标准工况验证、控制参数优化和动力等参数拉偏试验，其中阶段 A 的发射指令模型和单弹试验评估模型统一内聚到智能制导控制模型内部；最后，将通过阶段 A 验证的单个导弹装备回接到阶段 B 的海岛 4 弹 2 目标任务级场景，阶段 B 的发射指令/发射时序模型在发射链路中显式承载，任务级试验评估模型归入探测火控分系统，检查单弹装备在系统集成、资源分配和任务结果评估中的接口适配性和流程闭合。

### 2.3 设计约束

1. 当前正式库为 `Missile`，保持单一模型库多包扩展。
2. 统一使用 `Modelica.Units.SI`，不新增 `Modelica.SIunits` 依赖。
3. Modelica 基线为 `Modelica(version="4.0.0.TY.1")`。
4. 所有公开 `package/model/connector/function/record` 应具备中文描述字符串和 `annotation(Documentation(...))`。
5. 雷达、发射车、导弹动力、气动、通信、导引和识别均为 `Demo` / `Simple` / `Equivalent` 边界。
6. 阶段 A 输出的 `bestConfigId` 是阶段 B 的唯一导弹构型输入，阶段 B 不重新筛选构型。
7. A-P6 若启用，只允许优化 `maxCommandAccel`、`guidanceGainDemo`、`guidanceTimeConstantDemo`，不改变构型排序和 `bestConfigId`。
8. 多角度、风场、批量扫描只作为扩展工况结果记录。

## 3. 系统总体设计

### 3.1 系统组成

系统按阶段 A 和阶段 B 两条主线组织。

阶段 A 的单弹本体组成如下。

### 3.3 工作原理

阶段 A 面向单个导弹装备的设计开发、验证和试验闭环。首先围绕单枚导弹设计 4 种构型方案，即 `CFG-A/B/C/D`，通过不同动力拓扑和气动布局组合形成可对比的构型候选；随后在统一单弹单目标基准工况下开展仿真筛选，保持目标航迹、环境、初始条件和边界输入一致，只改变构型参数和可替换子模型，筛选出满足需求的推荐构型方案并输出 `bestConfigId`。

在推荐构型确定后，阶段 A 继续开展智能制导控制等单弹关键模型的开发和集成，完善动力、气动、结构、总体动力学、智能制导控制、发射指令模型、状态汇总和单弹试验评估模型之间的接口连接。发射指令模型和单弹命中/脱靶评估模型均作为智能制导控制模型内部逻辑，不再作为阶段 A 独立外部模块；标准工况验证重点检查单个导弹装备的飞行状态、智能制导指令、发射许可、健康状态和拦截评估输出是否闭环。

标准工况验证通过后，下一步进入控制参数优化。优化对象限定在推荐构型内的智能制导控制相关参数，例如 `maxCommandAccel`、`guidanceGainDemo` 和 `guidanceTimeConstantDemo`，优化目标是改善脱靶距离、制导指令平滑性和过载约束表现。控制参数优化不反向改变构型筛选结论，也不重新计算 4 种构型排序。

控制参数优化完成后，进一步开展动力等关键参数的拉偏试验。拉偏试验围绕推力、燃烧时间、质量、气动效率、动压/结构阈值、制导增益等参数进行有边界的偏差扫描，用于观察单个导弹装备在参数偏差下的飞行、制导、结构健康和拦截效果变化，识别单弹能力边界、敏感参数和后续需要补充验证的数据缺口。

阶段 B 固定使用阶段 A 的推荐构型，4 枚导弹统一采用 `selectedConfigId=bestConfigId`。最终场景设置为海岛环境下 4 个导弹打击 2 个目标，全场景模型按“海岛环境和目标输入 -> 探测火控 -> 弹目分配 -> 发射命令 -> 导弹飞行与智能制导控制 -> 探测火控内部试验评估模型完成命中/脱靶评估 -> KPI 汇总”的事件链运行，并输出 `scenarioPass`、`eventLogHash`、`resourceUsed`、`minMissDistance`、`interceptFlag` 等结果。

### 3.4 技术路线

1. 采用 Modelica 分层包结构表达系统组成。
2. 采用总线接口统一环境、目标、航迹、火控、导弹状态、健康状态、制导命令和 KPI 字段。
3. 采用阶段 A 单弹装备开发优先，按“四构型设计 -> 仿真筛选 -> 标准工况验证 -> 控制参数优化 -> 参数拉偏试验”的顺序形成单弹闭环，再扩展到阶段 B 任务级场景验证。
4. 采用 `Demo/Simple/Equivalent/Reserve` 模型边界，优先保障接口、流程和验证闭环。
5. 采用 Sysplorer `CheckModel` 和 `SimulateModel` 形成证据闭环。
6. 采用图形导出和人工复核提升模型可审查性。

### 5.2 模块内部逻辑

`SurfaceToAirMissile` 是阶段 A 和阶段 B 复用的单弹封装边界。内部逻辑按照“环境输入 -> 智能制导控制内部发射指令 -> 动力时序 -> 气动健康 -> 结构载荷 -> 总体动力学 -> 智能制导控制与单弹试验评估 -> 状态汇总”执行。飞行阶段管理、状态总线适配、发射指令适配和单弹评估逻辑当前内嵌在单弹封装/智能制导控制链路中，不作为单独一级组成。

`MissileBattery4` 管理 4 枚导弹实例，接收逐弹 `TrackBus`、`TargetStateBus`、`InfraredFeatureBus`、`FireCommandBus` 和 `MissileDatalinkBus`，输出 4 路导弹状态、健康状态、导引接收、智能制导命令、命中标志和最小脱靶距离。

`EngagementManagementSystem` 接收目标状态、红外特征、海岛环境、发射车健康状态和导弹组状态反馈。内部完成等效雷达探测、航迹过滤、火控门控、威胁排序、4x2 分配、逐弹目标映射、发射时序输出，以及任务级试验评估、事件记录、轨迹记录和 KPI 汇总。

`ScenarioEvaluationSystem` 作为探测火控分系统内部只读评估模型，不反向替代火控决策。它接收目标、分配、导弹状态、发射事件和阶段 A 接收状态，统计资源消耗、突防数量、拦截数量、事件哈希和场景通过标志。

| 质量边界 | `missileMass` | `missileMass >= epsMass`，燃尽质量不高于发射质量 | 动力和动力学计算使用质量保护量，A-P7 质量拉偏不得生成非正质量 |

## 8. 算法/模型/控制方法详细设计

### 8.1 算法原理

本方案采用演示级可解释模型，不采用真实装备算法。主要算法和模型包括：

1. 单目标匀速运动模型，用于阶段 A 固定目标航迹。
2. 三维点质量导弹运动模型，用于位置、速度、导弹等效加速度、过载和姿态占位量输出。
3. 简化动力时序模型，用于助推-续航和双脉冲拓扑差异表达。
4. 简化气动和结构健康模型，用于动压、马赫数、阻力、气动健康和结构载荷利用率输出。
5. 演示级智能制导控制模型，用于融合目标、航迹、红外、数据链和本弹状态，内部完成发射指令适配和单弹试验评估，输出 `aCmd[3]`、发射许可、制导模式、导引接收状态、命令抖动和单弹拦截评估结果。
6. 控制参数优化流程，用于在推荐构型固定后改善智能制导控制参数组合。
7. 动力等参数拉偏试验流程，用于识别单个导弹装备能力边界和敏感参数。
8. 等效雷达和航迹过滤模型，用于阶段 B 探测火控链路。
9. 确定性 4x2 弹目分配规则，用于演示海岛最终场景资源分配闭环。
10. 探测火控内部 KPI 统计模型，用于场景通过、资源消耗、突防、拦截和事件哈希统计。

### 8.2 数学模型

单目标运动：

```text
r_target(t) = r_target0 + v_target0 * t
```

导弹点质量动力学和加速度边界：

```text
a_missile =
  aCmd
  + thrustAcceleration * unitVelocity
  - dragAcceleration * unitVelocity
  - {0, 0, 0.05 * gravity}

der(r_missile) = v_missile
der(v_missile) = a_missile

accelerationNorm = norm(a_missile)
accelerationLimitRatio = accelerationNorm / max(missileAccelerationLimitDemo, epsAcceleration)
dynamicsOk = accelerationNorm <= missileAccelerationLimitDemo
```

弹目距离和最小脱靶距离：

```text
d(t) = norm(r_target(t) - r_missile(t))
minMissDistance(t) = min(minMissDistance(previous), d(t))
interceptFlag = minMissDistance <= hitRadiusDemo
```

阶段 A 构型筛选判定：

```text
scoreMissDistance_i =
  max(0, min(1, 1 - minMissDistance_i / max(interceptMissDistanceThresholdDemo, distanceScoreEps)))

scoreGuidanceCommand_i =
  max(0, min(1, 1 - guidanceCommandChatter_i / max(guidanceCommandChatterLimitDemo, accelerationScoreEps)))

scoreHealth_i =
  (motorOk_i + structureOk_i + aeroOk_i + controlOk_i + missileCommOk_i + onboardPowerOk_i) / 6

configurationScore_i =
  if not simulationOk_i or not noNaNInf_i then 0 else
    0.40 * scoreMissDistance_i +
    0.25 * scoreGuidanceCommand_i +
    0.20 * scoreHealth_i +
    0.15 * modelComplexityScore_i
```

阶段 A 控制参数优化：

```text
theta = {maxCommandAccel, guidanceGainDemo, guidanceTimeConstantDemo}
thetaOpt = arg min J(theta)
```

阶段 A 动力等参数拉偏试验：

```text
p_deviation = p_nominal * (1 + delta)
delta in [deltaMin, deltaMax]

boundaryReached =
  simulationOk == false or
  noNaNInf == false or
  structureOk == false or
  aeroOk == false or
  dynamicsOk == false or
  controlOk == false or
  minMissDistance > allowedLimit
```

拉偏试验只用于识别能力边界和敏感参数，不用于反向修改 `bestConfigId`。

阶段 B 等效探测包络：

```text
targetInEnvelope_i =
  range_i <= radarRangeMax and
  abs(azimuth_i) <= radarFovAz / 2 and
  abs(elevation_i) <= radarFovEl / 2
```

威胁排序：

```text
threatScore_i =
  threatWeightDistance * distanceScore_i +
  threatWeightClosing * closingScore_i +
  threatWeightAltitude * altitudeScore_i
```

阶段 B 场景通过判定：

```text
resourceUsed = sum(if launchCommanded[i] then 1 else 0 for i in 1:nMissiles)
targetPassCount = sum(if targetPassFlag[j] then 1 else 0 for j in 1:nTargets)
interceptedTargetCount = sum(if targetInterceptFlag[j] then 1 else 0 for j in 1:nTargets)

scenarioPass =
  stageAResultAccepted and
  resourceUsed == 4 and
  assignedTargetCoverage == 2 and
  targetPassCount == 0 and
  interceptedTargetCount >= minRequiredIntercepts
```

### 8.3 计算流程

阶段 A 计算流程：

1. 明确单个导弹装备设计边界、标准工况和验收判据。
2. 设计 `CFG-A/B/C/D` 四种构型方案，配置动力拓扑、气动布局和构型参数。
3. 加载环境、单目标航迹、智能制导控制内部发射许可和构型参数。
4. 对 `CFG-A/B/C/D` 分别执行单弹仿真筛选。
5. 记录 `maxOverload`, `minMissDistance`, `guidanceCommandChatter`, 健康状态和可运行状态。
6. 输出符合需求的推荐构型 `bestConfigId`、排序和选择理由。
7. 判断 `stageAExitPass`。
8. 在推荐构型下集成智能制导控制等关键模型，在制导控制模型内部完成发射指令模型、单弹试验评估模型和状态汇总接口闭合。
9. 执行标准工况验证，确认飞行状态、智能制导指令、发射许可、健康状态和拦截评估闭环。
10. 开展 A-P6 控制参数优化，输出优化前后 KPI 对比和推荐控制参数。
11. 开展 A-P7 动力等参数拉偏试验，记录能力边界、敏感参数和异常状态。
12. 将推荐构型和标准工况验证结果作为当前阶段 B 任务级场景验证的启动依据；A-P6 控制参数优化结果和 A-P7 拉偏试验结论作为后续阶段 B 迭代输入和能力边界补充材料，不作为当前阶段 B 启动门槛。

阶段 B 计算流程：

1. 检查 `stageAExitPass`、`bestConfigId` 和推荐构型可运行状态。
2. 将 `bestConfigId` 写入 `MissileBattery4.selectedConfigId`。
3. 初始化海岛环境、2 目标、4 弹发射资源和探测火控分系统。
4. 执行探测、航迹、威胁排序、弹目分配、发射时序和探测火控内部试验评估。
5. 4 枚导弹接收逐弹目标、航迹、红外和命令输入。
6. 统计命中、脱靶、突防、资源消耗和事件哈希。
7. 输出 `scenarioPass` 和报告变量。

### 8.4 参数设置

参数设置遵循以下原则：

1. 公开参数只作为演示基线，不外推真实装备性能。
2. 演示标定参数必须在参数来源表中登记。
3. TBD 或历史口径不一致的参数必须进入待确认项。
4. 阶段 A 四构型仿真筛选时，目标、环境、初始条件和边界输入保持一致。
5. 标准工况验证必须固定推荐构型，不再改变构型方案。
6. A-P6 优化时只调整三个控制参数，并记录优化前后 KPI。
7. A-P7 拉偏试验必须从推荐构型和标准工况出发，逐项记录偏差参数、偏差范围、结果变化和边界判断。
8. 阶段 B 只读取阶段 A 推荐构型，不重算 `SEL-SAM-*`，也不反向改变 A-P6/A-P7 结果。

### 8.5 收敛与异常处理

| 异常 | 处理方式 |
| --- | --- |
| 阶段 A 无有效构型 | 停止阶段 B，返回单弹动力、气动、制导或参数修正 |
| `bestConfigId` 越界 | 阶段 B 不启动，记录为阶段门控失败 |
| 标准工况验证不闭环 | 不进入控制参数优化，优先修复单弹接口、方程、参数或数值问题 |
| 控制参数优化无改善 | 保留基线参数，记录优化范围、目标函数和未改善原因 |
| 拉偏试验出现数值异常 | 标记能力边界或模型适用范围边界，保留异常参数组合和结果证据 |
| `simulationOk=false` 或 `noNaNInf=false` | 构型筛选结果标记为无效或不进入候选 |
| 除零风险 | 使用 `distanceScoreEps`, `accelerationScoreEps` 等保护量 |
| 命中短窗口穿越 | 使用事件锁存逻辑，保留原始几何距离用于诊断 |
| 结构/气动/控制健康失败 | 评分降级或优化目标增加罚项 |
| 图形视图不清晰 | 通过 `annotation(Line(...))`、可见 connector 和图形导出进行人工复核 |

## 10. 安全性与可靠性设计

### 10.1 安全边界

1. 本模型是数字样机演示模型，不用于真实装备设计和真实作战决策。
2. 传感器、制导、火控、分配和毁伤均为简化或等效边界。
3. `bestConfigId` 仅表示本案例仿真筛选规则下的推荐构型，不代表真实最优。
4. 参数优化仅用于演示级控制参数扫描，不用于真实控制律设计。
5. 外部接口预留默认只读，不允许绕过火控或制导模型写入核心状态。

### 10.2 保护机制

| 保护机制 | 说明 |
| --- | --- |
| 阶段 A 出口门控 | `stageAExitPass` 控制阶段 B 启动 |
| 构型合法性检查 | `bestConfigId in {1,2,3,4}` |
| 可运行性检查 | `simulationOk` 和 `noNaNInf` |
| 指令限幅 | `maxCommandAccel` 限制制导加速度命令 |
| 导弹加速度边界 | `missileAccelerationLimitDemo` 约束动力学输出的实际等效加速度 |
| 动压和结构阈值 | `dynamicPressureLimitDemo`, `structureLoadLimitPaDemo` |
| 健康总线 | 汇总动力、结构、气动、控制、通信和电源状态 |
| 事件锁存 | 命中事件锁存，减少采样时刻漏判 |

### 10.3 故障处理

| 故障/异常 | 处理策略 |
| --- | --- |
| 发射车健康失败 | 火控可用性降级，发射命令不应继续扩散 |
| 导弹分系统健康失败 | 通过 `MissileInternalStatusBus` 汇总并影响筛选结论或 KPI |
| 目标未探测 | 不生成有效航迹和分配 |
| 分配无效 | 不生成有效发射命令 |
| 阶段 A 未通过 | 阶段 B 不启动 |
| 图形接口缺失 | 进入人工复核问题记录，补充 connector 和真实连接线 |

### 10.4 日志记录

日志和证据记录包括：

1. 探测火控分系统内部 `EventLogger` 记录探测、分配、发射、拦截等事件计数和 `eventLogHash`。
2. 探测火控分系统内部 `TrajectoryRecorder` 记录目标、导弹和内部健康状态。
3. 探测火控分系统内部 `EngagementKpiCollector` 记录场景通过、资源使用、突防和拦截。
4. `07_结果输出/test_results` 记录 check / simulate 验证报告。
5. `07_结果输出/diagrams` 记录代表性 Diagram 图形证据。
